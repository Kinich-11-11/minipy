# MiniPy v5 后续升级清单

> 目的：在冻结的 v4.267 基线上继续完成 v5 的系统性重写和优化。此清单是执行顺序与验收门槛，不代表功能范围扩张；优先修正语义和状态一致性，再针对实测热点优化。每个条目均应由独立补丁、测试和报告支持，未经验证不得标记完成。

## 0. 当前基准快照

- 当前日期：2026-11-28。
- 唯一功能/回归基线：v4.267 冻结提交 `f7d7835c81cbbcf8ab04c5e0e0798c0cff8381dd`；基线 SB3 SHA-256：`d8c00d30a80e351a7caab8da304b1e1d3ce00e4fc5e5b84018f13a01bc370341`。
- 当前核心：`v5/MiniPy_v5-core.sb3`；SHA-256：`5a93246a42b80136db3ee99a3432b3c57cfc75362f1d894867c327c7a8ab5420`。当前锁定九个迁移补丁；后续变更应从该 v5 核心增量构建，不重放 v4 历史补丁链。
- 当前正确性快照：完整回归 1,675 项，v4.267 通过 1,613 项，当前核心通过 1,622 项；对比结果没有新增回归。主套件 177/178，尚有基线即未支持的 `exec` 差异。严格回归得分不是完整 Python 兼容率。
- 性能快照：ASCII 融合的五轮隔离测量显示长字符串负载中位数改善明显，但物理行、函数调用、矩阵负载中位数分别上升约 8.13%、4.72%、3.23%；各组样本有波动，不能据此推断统计显著性或普遍提速。
- 详细证据：`ARCHITECTURE.md`、`FEATURES.md`、`REPORT.md` 和 `reports/`。本快照仅在相关测试、核心哈希或工具链发生变化时更新。

## 1. 执行约定

- [ ] 开始每个条目前先记录当前基线 SHA、测试结果和目标工作负载；变更后重建、重测并记录实际产物 SHA。
- [ ] 一次只改一个主要机制，优先通过现有补丁构建系统接入；只有已经验证稳定且有意提升为基座时，才更新核心锁。
- [ ] 不从其他 MiniPy 版本搬运实现；Scratch 项目继续承担解释器核心执行，不把功能外包给宿主语言或外部服务。
- [ ] 不为了分数放宽 oracle、跳过历史有效用例或硬编码测试输入；CPython 仅作为语义参照，先确认适用版本和环境依赖。
- [ ] 每项同时记录正确性结果、运行时间（至少报告样本数、中位数和区间）、静态体积/结构影响及已知代价；调用次数只作为热点线索，不冒充 CPU 时间。
- [ ] 出现回归时先定位根因；修复前不得把该阶段提升为 v5 核心。

## 2. P0：语义、功能和状态可靠性

### 2.1 收敛剩余差异

- [ ] 对 `reports/live-diff.json` 中的差异逐项归类：可观察语义、异常类型/消息、时钟依赖、对象地址等。优先处理确定的可观察语义错误；环境依赖项不得伪造为确定性失败。
- [ ] 为每个修复增加最小、独立、可重复的永久回归用例，并确保原始基线和新核心均有结果记录。
- [ ] 保持 `exec` 等 v4.267 基线未实现的能力明确列为既有范围限制；除非另行决策，不把它混入本轮优化目标。

### 2.2 可变对象、别名与容器协议

- [ ] 覆盖嵌套列表/字典/集合的共享引用、浅复制、深复制、原位修改、重绑定、删除及对象身份组合；重点检查共享子容器在函数参数、返回值和容器嵌套间的传播。
- [ ] 明确统一对象引用/存储协议，避免值相等、序列化内容相同与对象同一性混为一谈；用组合测试证明别名、复制和解绑语义。
- [ ] 审核字典视图在创建后容器改变时的行为，以及 `keys/values/items` 与迭代器的生命周期、顺序和失效边界。
- [ ] 覆盖迭代器消费位置、`map`/`filter` 组合、生成器暂停/恢复/关闭、异常传播与 `finally` 执行；确保异常后下一次 RUN 状态干净。

### 2.3 控制流、调用帧及异常恢复

- [ ] 建立 `return/break/continue/raise/yield/with/finally` 交叉组合回归，包含递归、嵌套异常处理及生成器退出。
- [ ] 验证调用帧入栈/出栈、值/向量暂存、控制栈与生成器栈在成功、异常、HALT、超限和连续运行后的平衡。
- [ ] 对连续执行不同程序、运行错误程序后再运行正常程序、暂停/停止后重启进行多轮测试；报告残留状态和成功率。

### 2.4 词法和源代码边界

- [ ] 覆盖 ASCII 标识符/数字/运算符、Unicode 非法字符、字符串与三引号、注释、转义、tab、CR/LF、超长行和无效输入的语义组合。
- [ ] 保持字符校验的精确性；不得用大小写不敏感的 `contains` 近似替代 ASCII 字符集合判断。
- [ ] 检验物理行映射在续行、分号、多行 suite、注释及内部辅助行下的稳定性。

## 3. P1：性能与架构主路径

### 3.1 ASCII 校验融合复测与优化

- [ ] 将长字符串、短语句、长标识符、数字密集代码、大量注释、错误 Unicode、混合字符串/注释分别拆成微基准，避免单一 workload 掩盖路径差异。
- [ ] 延长重复次数并交错运行前后核心；观察中位数、区间、启动/预热差异和工作负载规模趋势，确认当前中位数变化能否复现。
- [ ] 分析 tokenizer 中逐字符验证、Scratch 造型切换和控制流分支的实际成本；尝试替代方案时同时验证字符精确性、积木规模和目标 VM 行为。
- [ ] 只有在长字符串收益仍保留且代码型负载无可重复的实质退步（或退步已被有证据的其他方案消除）时，才确认该优化最终形态；否则选择正确、整体更稳健的实现。

### 3.2 名称解析与作用域热路径

- [ ] 以 profile 复核 `nameEq776`、`compareText`、`cellResolve763` 等热点在典型负载中的调用量，并补充代表性作用域规模和名称冲突基准。
- [ ] 分析名称表线性搜索、大小写精确比较、闭包单元查找及模块/局部变量访问的端到端成本；调用次数不得单独当作时间成本。
- [ ] 评估索引/缓存的收益与失效条件（作用域切换、绑定删除、重绑定、闭包和异常）；不能证明生命周期安全时，不引入缓存。
- [ ] 如更换名称解析算法，验证大小写敏感、遮蔽、`global/nonlocal`、删除、闭包捕获、模块别名和连续执行，并比较不同名称表规模下的时间与空间增长。

### 3.3 表达式与语句执行核心

- [ ] 以实测热点定位 `execute`、`evalCtx828` 及运算/属性分派中的高成本路径，先记录调用图和真实 workload，再决定拆分或重写。
- [ ] 定义统一的表达式结果、异常/控制信号和执行位置协议；拆分大过程时避免复制一套并行求值机制。
- [ ] 对算术、比较链、短路、调用参数求值顺序、索引/切片、属性副作用和异常传播增加组合测试。
- [ ] 评估是否需要更简洁的内部表示；不预设必须引入字节码或 AST，也不以新增抽象层数量作为重写成绩。

### 3.4 函数调用、帧和临时数据

- [ ] 分段测量帧复制、参数绑定、闭包单元读写、返回值传递及 RUN/STEP 调度；区分初始化成本与程序执行成本。
- [ ] 在 `frames` 单一 schema 基础上检查是否能减少帧复制和重复状态存储，保持 UI 状态保护与控制/生成器状态分离。
- [ ] 对深调用、递归、多个参数、异常退出和生成器暂停恢复做压力及资源增长测试；记录列表峰值，并说明它不是宿主堆字节数。

### 3.5 容器和内置操作

- [ ] 对高频列表/字典/集合操作、成员查询、排序、复制和迭代做规模化基准，识别线性搜索、重复序列化或多次复制。
- [ ] 统一相同对象行为的底层读写路径，减少因类型标签分支而重复实现；保持 Python 可观察语义优先。
- [ ] 为每项算法注明实测规模与复杂度边界，避免只用小输入样例推断大输入收益。

### 3.6 源码预处理与启动

- [ ] 分开测量载入、VM 启动、绿旗初始化、空程序预热、源代码拆分/缩进布局和首次执行时间。
- [ ] 覆盖空程序、短程序、大量物理行、长续行、深缩进及注释密集输入；确保输入快照和原始行映射不被优化破坏。
- [ ] 只有基准证明可减少重复扫描/复制时才重写相应步骤，并验证大小规模趋势及峰值列表资源。

## 4. P2：补丁、测试、可移植性与发布质量

### 4.1 补丁和基座治理

- [ ] 为每个新增补丁声明唯一职责、显式依赖、写集、适用核心哈希和独立测试；检查构建顺序与重复写冲突。
- [ ] 对稳定、验证充分且后续不应重复应用的机制，评估是否沉淀进 v5 核心；保留变更账本和可从冻结 v4.267 复现的构建链。
- [ ] 定期清理仅限本轮确认的试验产物；保留正式报告、回归用例和复现实验所需数据。

### 4.2 测试和诊断

- [ ] 维持 v4.267 固定回归、CPython 差分、功能组合、构建校验、双 VM、生命周期、压力和基准测试。
- [ ] 每个历史缺陷建立永久回归测试；测试结果需核对程序结束、输入源码未变、帧栈平衡、输出、异常和行号。
- [ ] 把用户程序异常、解释器内部失败和不支持行为区分呈现；错误信息不得依赖偶然的宿主栈文本。
- [ ] 验证报告、核心 SB3、`core-lock.json` 与测试产物哈希一致；统一报告基准环境、Node/Python/VM 版本和测量方法。

### 4.3 Scratch 运行环境兼容

- [ ] 明确目标 Scratch VM/编辑器及其版本；验证导入、绿旗、RUN/STEP/HALT、输入、输出、导出和编辑器工作区加载。
- [ ] 在至少两种支持的 Scratch VM 入口重放语义组合用例；对未实测环境明确标记，不外推兼容结论。
- [ ] 审查解释器是否依赖未保证的 VM 行为；必要适配集中在边界，不能把环境分支散落进语言核心。

## 5. 每项优化的完成门槛

只有以下项目全部可核验，才可将单项标记为“完成”：

- [ ] 目标问题、受影响机制、风险及不做方案的理由已记录。
- [ ] 有基线和候选的固定 SHA，构建可重复且产物与锁文件一致。
- [ ] 相关单元/组合/历史回归通过；没有未解释的新增失败。
- [ ] CPython 参考结果已复核，环境依赖和差异分类明确。
- [ ] 性能对比使用相同输入和配置，报告样本数、中位数、范围及绝对值；有波动或负载回退时如实保留。
- [ ] 说明 SB3、project.json、积木/变量/列表规模或运行期资源的变化及其测量边界。
- [ ] ARCHITECTURE/FEATURES/REPORT 和补丁账本已同步；已知问题与未达标项未被隐藏。

## 6. 最终交付前的总体验收

- [ ] v4.267 冻结标识、功能索引和可复现构建链完整。
- [ ] 所有有效基线功能有测试或明确的适用限制；历史有效行为无新增回归。
- [ ] 重要 Python 语义差异已有逐项处理结论；未解决差异列出影响和后续方案。
- [ ] 真实 Scratch 环境导入和 UI 流程经过验收，不以静态 SB3 校验替代。
- [ ] 压力、连续执行、异常恢复及不同规模性能结果可复现。
- [ ] 十二项原则均有证据、边界和未达标说明；没有把阶段性核心候选误称为完整 MiniPy v5。
