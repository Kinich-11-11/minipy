## 4. 十二维验收及剩余工作

| 原则 | 证据与边界 |
|---|---|
| 正确性 | 严格回放及二次 CPython 对照如上；剩余失败保留在清单。 |
| 简洁性 | 块数、分支、调用点见上；去除 132 个单写单读暂存中转。 |
| 一致性 | RUN/STEP 共用一个内置执行体；一套帧布局生成入栈/出栈；模块级与局部可变别名共用作用域单元。值堆仍有多种协议。 |
| 高效性 | 同机多轮耗时和波动如上；布局配对消除逐行向后找结束行。单项退步或波动大的负载应扩大样本再定论。 |
| 轻量性 | 归档、JSON、变量/列表均静态实测；资源哈希不变。暂存单元是采样下界，未精测宿主堆。 |
| 稳定性 | 两侧均执行 60 次不复位连续 RUN；暂停/HALT 后新 RUN、输入、超限恢复见 lifecycle 原始检查。未做数小时浸泡。 |
| 可维护性 | 静态调用边见上；增加帧字段只改 frames 的一份声明。未对人类修复工时作虚假估算。 |
| 可扩展性 | 8 个迁移补丁职责显式；后续补丁直接读 v5 锁定核心。未为测行数而扩大语言范围。 |
| 可测试性 | 四项构建单元测试、真实 VM 集成、冻结和实时 oracle、故障恢复、双 VM 与性能套件可分别执行。不是逐积木路径覆盖率。 |
| 可调试性 | 错误行和 `Code`/映射有断言；可离线反汇编和读取真实运行后的状态；核心不挂调试监听。 |
| 可预测性 | 同工具链字节级重建、原始分布、超限与恢复均有检查；不固定 Python 允许随机的行为。 |
| 可移植性 | 另在仓库 scratch-vm 2.1.46 源码入口运行 21 项组合（基线 14/21、候选 21/21）；5.0.300 是主验收环境。未实测新版在可视 Scratch/CCW 编辑器的导入及交互，不以静态资源验证替代。 |
