### v4.206 的补丁清单

* **P522** `__sub__`/`__mul__` 运算符重载：在 `rightside` 的 `*` 站点与通用 binerr 站点
  装分派门（`lefttype=='O'` 守卫 + callmeth 后 `stop this script`，防级联二次报错）；
  同时给 P427 的 `+` 门补 `lefttype=='O'` 守卫（`1 + 'a'` 不再拿数值当实例号）。
* **P523** 构造实参扫描：`*` 只有前一个 token 是 `(`/`,` 时才算星号解包
  （`Vec(self.x * k, …)` 不再被误判，B6 真根因）。
* **P524** `calluser` 的 vmOn=2 元组拆参前清空 `UArgV/UArgT`（调用方残留不再串进实参表）。
* **P526** N 记号尾零规范化（含 ev/evtype 保存恢复，防 tokenize 内的 substr 污染）。
* **P527** 程序结束把 `pmbuf` 里的行缓冲落盘（`print(..., end='')` 的尾巴不再丢）。
* **P528** `range` 表达式快路径要求 `Tok[lo+1]=='('` 且深度**到 hi 才归零**
  （`range(3) == range(3)` 不再把第二个调用的参数区吞进 crng）。

### 本轮踩的坑（下轮注意）

- **expectError 标记是 `### !用例名`**，不是 `!### 用例名`——写错位会让该行被当成上一条
  用例的代码行（4 例"回归"全是这么来的，案例总数 581→577）。
- **`JSON.stringify(块)` 只含引用 id**：匹配条件/子树必须把 `reach()` 的每个块都
  stringify，或直接检查**被引用块**的 opcode（P523/P528 两次踩坑）。
- **补丁执行期 `parent` 指针不可靠**：只有 tail 的 `relinkParents` 才重建；
  要定位宿主 IF/分支首句一律按 SUBSTACK 链行走（P522/P525/P530 三次踩坑）。
- **IEEE 缩放的再舍入**：`2.675*100 === 267.5`（真值 267.4999…982 被乘法的舍入
  抬成恰好半偶点）——任何"乘 10^n 再四舍五入"的实现都救不了这类值，必须走
  精确十进制展开（见 §1 round）。
- **新全局变量不在 fpush 保存集**：保存集在 P14 构建期固定；补丁新引入的全局
  （如 p31nid）跨帧不会被还原，嵌套调用会互相覆盖（P529 因此回退，见 §3）。
- **`chain()` 只收数组**：`chain(单块id)` 会按字符迭代生成垃圾块（P527 踩坑）。
- **`REPEATU(cond)` 是"直到 cond 为真"**：循环条件要写**停止条件**（P525 踩坑）。

## §1. 数值底座（11 例，纯显示/精度，v4.206 未动）

| 用例 | 现状 | 说明 |
|---|---|---|
| cov1 big int precision / divmod big / integer division precision | 精度丢失 | 文档 §2 已声明（JS number，53 位） |
| cov10 int to str of very large | 科学计数法 | 同上 |
| cov10 large and small floats / sum of floats | 显示差异 | `123456789.12345679` 被打印成 `…789`；`0.6` 变 `0.6000000000000001` |
| cov1 float conversions / covX negative zero variants / 82 negative zero float | `-0.0` 丢符号 | `float('-0.0')` 输出 `0.0`（字面量 `-0.0` 已正确） |
| cov1 round no ndigits / cov10 round returns | 2.68 vs 2.67 | 见下 |

### round 的根因（v4.206 定位，补丁回退）

`round(x, n≥0)` 走 `mrt = x*10^n; roundpy(mrt); ev = 结果/10^n`。IEEE 乘法会把真值
略小的数**舍到恰好 .5**：`2.675*100 === 267.5`（2.675 的双精度真值是
2.67499999999999982…，乘积被就近舍入抬到 267.5）→ 半偶进位 → 2.68，而 CPython 按
双精度的**精确十进制展开**判定 → 2.67。曾实现 `rounddigits`（`I=floor(|v|·10^(nd+8))`
看末 8 位），但 1e10 量级的探针乘法同样会被再舍入到平局点，逐级 ×10 对比又受
"相对误差恒定"限制。**正解需要双精度的精确十进制展开**（等价 `toFixed(30)` 的
长除法），块级实现成本高，暂缓。

### 负零（v4.206 定位，补丁回退）

`-0.0` 字面量与 `str(-0.0)` 已正确；只有 `float('-0.0')` 丢符号。修法应在 float()
分支 `mkfloat` **之后**把 ev 置为 `'-0.0'`（mkfloat 自身会把 -0 规范化掉），
但该分支在 callfn/callfnW 两份克隆里形态不一（`fn=='int' OR fn=='float'` 与
`fn=='float' AND infnan==0` 两个 IF），插入点未唯一定位。下轮先用 dbg 探针
实测分支命中点再装。

## §3. 实例模型（2 例 + 1 例部分）

| 用例 | 现状 | 根因 |
|---|---|---|

### 嵌套构造的身份错乱（v4.206 深挖，未解）

DbgLog 探针（`_dbg522.js`）实测 `v1+v2` 的构造过程：
`CTORIID=3`（新实例号已分配）→ `CU fn=Vec.__init__ vmOn=2 nUArg=1` →
**`__init__` 体完全没有执行**（无任何 IAttr 写入）→ `ev=p31nid/iid` 拿到的是
旧实例。最终 `IAttrVal=[9,12,4,6]`：v1 的行被 `v1*3` 的结果覆盖、v2 的行被
`v1+v2` 的结果覆盖，结果实例自己的行从未存在。要点：
- `callmeth` 在方法帧里调构造器时，`calluser(UArgV/UArgT)` 的入口仍带上一层的
  残留（`nUArg=1`）；P524 清了 UArgV，但**绑定与函数体仍未执行**，说明
  `vmOn==2` 的绑定分派或 `FnStart/FnEnd`（fi 定位）在这一路径上失效。
- 顶层的同形构造（`v1=Vec(1,2)`）完全正常 ⇒ 差异只在"方法帧内"。
- **P529 实验（回退）**：把构造器收尾 `ev = iid` 改成 `ev = p31nid`（开局保存的
  新实例号）能修 B7，但**搞坏 cov6 的 `V(1)+V(2)`**——因为 `p31nid` 是补丁新
  全局、**不在 fpush 保存集**，嵌套/跨帧时被覆盖，而 `iid` 在保存集里。要同时
  修两处，需把新变量登记进保存集（重建 fpush/fpop，或复用已有被保存的临时量）。

### B7 类属性写路径

`Counter.count += 1` 的读路径已由 P511 改用 `clsiid`，但**写**路径（增强赋值
重派发后的回退）仍 `set iid = Tok[1]`（类名）→ 构造器收尾 `ev=iid` 拿到字符串
→ 后续 `a.bump()` 的 `InstCls[类名]` 越界。修法同 §3 的保存集问题。
