# MiniPy 已知问题清单（基于 v4.201 实测）

**构建**：`MiniPy_v4.201.sb3`（2026-10-28，33,385 块）
**对照**：CPython 3.14（oracle），15 套 581 例 + 补充 82 例，串行、各自私有临时文件。
**总量**：
- 581 例中 **43** 失败（v4.200：55）
- 82 例补充中 **10** 失败（v4.200：15）
- **真实失败合计 ≈ 51**（v4.200：≈68）

> 排名判据：**影响体验（静默错 ≫ 报错） × 覆盖广度（学生日常写法出现频率）**。
> 所有结论均由 `runall.mjs`/`run_iso.mjs` 实测，逐例用 `cmp131.cjs`/`gdiff.cjs` 核验。

### 本轮新增补丁（p492–p498）

* **P492** methodcall2：列表方法（pop/append/…）走 `pathset` 写回接收者时把 `ev/evtype`
  覆盖成路径中间值（实例），吞掉方法返回值。修法：pathset 前后保存/恢复。
* **P493** 绑定方法：`m = t.get` 返回 `evtype='M'` 值（`"<实例id>.<方法名>"`）；
  callfn 入口按 Types=='M' 分派 callmeth；名字调用路径的 not-callable fail 前加 M 逃生门。
* **P494** lcmp：O/O 且 `<类>.__lt__` 已注册时用 dunder 比较
  （`assign('__ltarg', 右操作数)` + `tokenize('__ltarg')` + callmeth —— 实例不能 repr 传参；
  第二次比较是 `lt(b,a)`，inst 取 LcStk 栈顶）。sorted/list.sort/min/max 全部受益。
* **P495** filter(None, xs)：else 分支整体换成 `truth(mpel, mpelt)`（解释器权威真值）
  + 元素 `lesc` 后再 enc（修嵌套元素边界）。
* **P496** joinlines：行尾在单引号字符串内且以反斜杠结束时，剥反斜杠并以空串连接
  （CPython 字符串内 `\<换行>` = 空）；三引号行为不变。
* **P497** 生成器游标：新过程 `gslice gid`（ItSrc[gid] 从 ItPos 切到尾并推进）与 `gconv`
  （G→登记 GIt/GId→gslice）；callfn `list()` 的 Y 分支改为切片（P461 行为升级）；
  cdo 的 iterable 守卫前与 forloop 分派前接受 G（转 L）。next() 本就推进 ItPos，
  于是生成器**函数**的复用/续读语义与 CPython 一致。
* **P498** reglam：把 P383 的 regdef 闭包快照原样接到 reglam 末尾 ⇒
  `def adder(n): return lambda x: x+n` 的 lambda 能拿到外层局部变量
  （lookup 末尾的 FnStack 回退查找是现成的）。

### 本轮踩的坑（下轮注意）

* `spliceAfter(afterId, firstId)` 的第二个参数是**块 id**，传 `[id]` 数组会让 `next` 变成数组、
  子树被 prune 成孤儿（STRUCTURE ERROR orphans>0）。本轮踩了三次。
* `JSON.stringify(block.inputs)` 不含引用块的内部文本——按字面量定位块必须**顺着引用走子树**
  （`subtreeHas` 模式），且值可能是 shadow 包裹（`VALUE=[1,[4,"0"]]`）要拆一层。
* 用户层形参按名字查找的是 Names 表（不是 Scratch 变量）：给 dunder 传实例只能
  `assign('__ltarg', …)` 注册成用户变量再 `tokenize('__ltarg')`。
* eval 里有两套属性读取分支（`iid`+`Tok[lo+2]` 的 3 记号版与 `atid`+`atnm` 的链式版），
  插桩时两个都要打。
* `assign` 会把新变量放进用户 Names 表——用作跨调用传值的临时变量名要足够怪（`__ltarg`）。

## 1. 闭包 `nonlocal` / 帧内未绑定（剩余约 4 例）

- `cov5 nonlocal keyword` / `covC nonlocal keyword` / 补充 `nonlocal counter` → `SyntaxError: unsupported statement`
- `cov5 closure counter attempt without nonlocal` → 输出 `1 1`（CPython 抛 UnboundLocalError）
- 补充 `UnboundLocalError name exists` → 抛基类 NameError（属异常**产生**侧）

> 方向：P498 已让返回的 lambda 能**读**外层变量（按值快照）。`nonlocal` 需要写回：
> 在快照里记下"该名字来自闭包"，`assign` 时若名字是捕获名则同步写回 CloV。
> `closure counter without nonlocal` 需要"函数体内被赋值的名字是本地"的静态判定，
> 或在 assign 前检查名字是否为捕获名。

## 2. 生成器对象标识（剩余约 6 例，核心是 genexp 惰性）

- `cov7 comprehension reusing a generator` → `[0,1,2] [0,1,2]`（应 `[0,1,2] []`）
- `cov7 generator expression vs list comp` → `next(g), list(g)` 得 `0 [0,1,2]`（应 `0 [1,2]`）
- `cov7 generator short circuit`（any/all 求值不短路）
- `cov7 generator exception propagation`（body 在 next 时一次跑完）
- `cov7 iterator protocol on custom class`（`__iter__`/`__next__`）
- `covZ genexp is a list`（文档已声明的偏差）

> 方向：生成器**函数**的游标已修好（P497）；剩下全卡在 genexp 急切物化为 L
> （§10 已声明偏差）。本轮试过"P235 括号剥离点把内层含 for 的结果改标 G"（P499），
> G 化本身成功但 `next(g)` 立刻 StopIteration（疑似 printargs 求值顺序/双重求值），
> 已回退。重试前先探明 `print(next(g), list(g))` 的实参求值顺序。
