## 第 27 轮：S11 的「断点单步」+ 布尔算术修复 + `divmod`

### 1. 断点（`#!bp`）——方案 S11 明列的最后一项

用法（和 `#!dump`/`#!code` 一样，参数写在**下一行**）：

```python
#!bp
12          # 在字节码地址 12 处停下（先跑一次 #!trace 就能看到每条指令的 pc）
i = 0
...
```

实现：RUN 口先清 `bp`，读 `Code[1]='#!bp'` 时把 `Code[2]` 写进 `bp`；VM 主循环在**取指之前**
比较 `pc = bp`，命中就置 `halted=1`、`bphit=1` 并把 `status` 写成 `Breakpoint at <pc>`，
RUN 口末尾只有在 `bphit=0` 时才把状态覆盖成 `Finished`。

单步：外壳的 `speed` 开关置 0 时，主循环每帧只执行一条指令（第 21 轮接的）；
追踪：`#!trace` 每条指令打印 `pc op sp= fr=`。三者合起来就是 S11 要求的「断点单步」。
新增 `_work/v5/btest.json`（4 例）：无断点跑完、断在第 1 条、断在第 6 条（只打印了 'a'）、
循环中断在第 12 条 —— **4 / 4**，status 分别是 `Finished` / `Breakpoint at 1/6/12`。

## 第 25 轮：字符串 `%` 格式化（补上第 24 轮回退的坑）+ `**kwargs`

### 1. `'%d-%s' % (3, 'x')` 现在真的能用了（6 / 6）

第 24 轮我把字符串 `%` 分支加进了 `arithBlock` 里，用探针查了半天「为什么字符串走不到那条分支」。
本轮把探针插到 `binBlock` 的每个分支前，一次就看清了：

* 目标分支根本不在 `binBlock`，而在 **`arithBlock`**；
* 而 `arithBlock` 只在**两个操作数都是数字**时才会被调用（`binBlock` 里那条守卫的条件是
  `isNum(va) and isNum(vb) and rt='N' and op in + - * / // % **`）；
* 所以字符串左操作数**永远不会**进 `arithBlock` —— 数值 `7 % 3` 能到，字符串不能，完全对得上探针结果。

修法：把 `strFormat` 与那条分支搬到 `binBlock`（和 `+`、`*` 的字符串分支放在一起），
`arithBlock` 保持原样（数字取模）。支持 `%s`（str）、`%d`（向零截断）、`%f`/`%r`（普通 repr）、`%%`，
右侧可以是元组或单值。新增 `_work/v5/ptest.json`（6 例，CPython 真值）：**6 / 6**。

### 2. `**kwargs`（原来直接 `SyntaxError: bad parameter list`）

三处修改：

* 词法把 `**` 当**一个**两字符运算符（`OPS2`），所以参数循环里 `isO('*')` 永远匹配不到 → 解析器补 `isO('**')`；
* 参数列表的合法性检查只允许「标识符 / `,` / `*`」，`def f(a, **k)` 在逗号之后就被判非法 → 补 `**`；
* VM 侧：连续两个 `*` 把 `starm` 置为 2（`*args` 是 1），收尾时走新分支——遍历 kw 字段，
  跳过已被具名参数占用的，其余塞进一个新 map，键用**带 `S` 标签的原名**（否则 `k['z']` 查不到），
  值本身也要带 `D` 标签（否则打印出来是裸的 map id）。

新增 `_work/v5/ktest.json`（5 例，CPython 真值）：**5 / 5** —— `def f(**k)`、`def f(a, **k)`、
`def f(*a, **k)`、`k['z']` 取值、空 kwargs。

## 第 23 轮：`next()` 与**真正的** `sorted(key=)`

### 1. `next(g)`（编译器内联）

内建函数无法回调用户代码，所以 `next(g)` 由编译器展开成一段恢复序列（`ITER/NEXT/NCHK`），
把产出值先存进临时变量、弹掉两个迭代器槽位再压回；生成器结束时跳到 `RAISE StopIteration` 分支。
支持 `try/except StopIteration`、`next` 与 `for` 混用、多个生成器交替。

### 2. `sorted(key=...)`：原来是**静默的错误答案**

第 21 轮那次「扩展套件 30/30」其实是假通过 —— 当时 `sorted` 里写着一段占位实现：
「有 key 就**反转顺序**」，对 `key=lambda n: -n` 恰好等价，对 `key=len` 就完全错了。
本轮换成真实现：

* 编译器把 `sorted(X, key=K)` 展开成「遍历 X、逐元素求 `K(v)`、把 `(K(v), v)` 追加进临时列表」，
  再调用新内建 **`__sortpairs(pairs, reverse)`**（按元组首元素排序后取出第二元素）；
  元组比较复用了第 20 轮做的 `cmpPair` 字典序比较。
* `sorted(X, reverse=R)`（没有 key）仍走内建，`reverse` 用 `truthOf` 判断后原地反转。
* 出现不支持的 key 形态时**响亮地**抛 `NotImplementedError`，不再给错答案。
* 新增测试 `_work/v5/stest2.json`（6 例，CPython 真值）：**6 / 6** —— `key=lambda n: -n`、
  `key=lambda s: len(s)`、无 key、`reverse=True`、命名函数 key、`list.sort()`。

### 3. 顺带修掉的解析器 bug（影响面比 sorted 大）

**关键字实参的值是 lambda 时，kwarg 名字会丢**：`f(x=lambda ...)` 会退化成位置实参（AST 里
call 的 kw 串变成 `,,`）。原因是 `pushV(nd)` 只接受一个参数、名字从 `kwpend` 读，而 lambda 的
上下文收尾时 `kwpend` 已被函数体求值清空；现在在收尾处把捕获的 `kwlam` 写回 `kwpend` 再压栈。
（这个 bug 之前让 `sorted(key=lambda …)` 根本无法内联。）

### 4. 又一次踩到 `setAt` 只加长一格的坑

`reverse=True` 传进来是 `B1`，而 `payInto` 会把标签字符剥掉得到 `1`，于是 `= 'B1'` 永远不成立、
反转静默失效。改用 `truthOf(arg(3), …)` 判断真值。

| 状态 | 新列表 `GnFid/GnPc/GnEnv/GnDone/GnSp/GnStk`，生成器值 = `G<id>` |
| 创建 | `def` 体里出现 `yield` → 解析器给该 def 节点打 `NdG='g'` → 编译器发 `GDEF` → `defBlock` 写 `FnFlags='g'`；调用时**只绑参数不压帧**，把参数环境存进 `GnEnv` 并返回生成器对象 |
| 恢复 | `NEXT` 见到 `G` 迭代器 → 压入 `FrKind='G'` 的帧（`FrRet = pc+1` 指向紧随其后的 `NCHK`），`pc = GnPc`（首次为函数体入口），并把 `GnStk` 里保存的栈槽按序压回 |
| 挂起 | `YIELD` 保存 `pc+1` / `FrEnv` / 栈槽到 `GnStk`，弹帧并把产出值压回调用者栈顶 |
| 耗尽 | 生成器帧执行 `RET` → `GnDone=1` + `gstop=1`，不压返回值；`NCHK` 看到 `gstop` 就跳到 `for` 的结束标签 |
| 迭代 | `ITER` 对生成器直接透传；`for` 循环在 `NEXT` 后多一条 `NCHK`（对列表迭代是空操作） |

新增指令 **2 条**：`YIELD`、`NCHK`；新增 `GDEF`（带生成器标志的 `DEF`）。

### 本轮抓到的三个真 bug（全都很隐蔽）

1. **`L.setAt` 只能把列表「加长一格」** —— `setAt(list, i, v)` 在 `i > len` 时走 `ladd`，所以
   「往空列表的第 24 格写」会写到第 **1** 格。`FnFlags` 从来没为 23 个内建函数预填过，
   于是生成器标志被写到 `FnFlags[1]`，`callBlock` 读 `FnFlags[24]` 自然是空的。
   修法：内建注册时一并写 `FnFlags` 占位。（同样的坑：`Gn*` 系列必须按 gid 顺序写，才能靠加长一格生效。）
2. **`NEXT` 的返回地址用错了操作数** —— `ia()` 是跳转目标（`for` 的结束标签），不是「下一条指令」。
   结果 `YIELD` 恢复后跳到程序末尾而不是 `NCHK`。修法：`FrRet = pc + 1`。
3. **节点表 `NdG` 与节点 id 不同步** —— 只有 `nodeK` 写 `NdG`，`nodeN / nodeFromHeap / pexpr` 的
   节点创建路径没写，`NdG` 比 `nTop` 短；于是「第 2 个 yield 之后创建的 def」标记会因越界而**静默丢弃**，
   表现为「只有第一个生成器函数生效」。修法：6 处节点创建点全部补 `ladd('NdG','')`。

另外：编译器任务是 **LIFO** 执行，`NCHK` 必须写在 `NEXT` *之前* 的源码位置才会排在它后面执行（老坑重犯一次）。

## 第 21 轮（性能 + §10 变量数）

### 1. 调度决策树（`vm.js` 的 `dispatchTree`）

原来 `dispatch` 是 **45 个平铺的 `如果 op = "X"`**，每条指令平均跑二十多次比较。
改成按操作码**首字母**分组的决策树（组内按热度排序）：热指令 1~3 次比较，冷指令 ~2 次。
同一环境下前后对比：**36,000 → 50,000 指令/秒**（+40%）。

试过但**否决**的方案（如实记录）：

* 把 14 条热指令摊平成一条链（`如果 op = "PUSHV"` …）——实测**更慢**（36k vs 50k）：
  整串比较 `Cast.compare` 对字符串要走 `Number()` + `toLowerCase()`，比 `letter(1, op)` 贵得多。
* 把 `vm_run` 改成 warp（无刷新执行）——只快 19%，但 warp 线程**会忽略显式 `等待 0`**，
  时间片失效（整个程序在一个 `_step()` 里跑完，UI 每帧卡 500ms），已回退。

### 2. 时间片改成按墙钟

固定「每 2000 条指令让帧」改成「每 1000 条检查一次，距上次让帧 ≥16 ms 就让帧」；
单步模式（`speed = 0`）仍是每帧一条指令。顺带把每指令一次的 `Code[1] = "#!trace"` 检查
提到循环外（`dbg` 变量），把 `ticks mod 1000` 换成 `nchk` 倒计时。

### 3. §10 变量数：294 → 196（`regalloc.js` 大改）

诊断：**265/303 个变量只被一个自制积木引用**，不是跨调用共享状态；`vm_run` 一个脚本里就有
308 个不同名字的临时量。旧分配器**按变量名**着色（一个名字一个 web），只压到 145 个颜色。

新分配器：

* 先按脚本的**结构化块序**（DFS：语句 → 条件/参数 → SUBSTACK）线性化，给每个块一个序号；
* 把每个变量按 def-use 切成 **web**，web 的活跃区间 = [首次出现, 最后出现]；
* 用**区域 + 区间混合规则**着色：两个 web 的区域在**不相交子树**里（永远不可能同时活跃）→ 可共用；
  同一个区域内且区间**不重叠**（该区域按块序直线执行）→ 可共用；区域可比较但不同 → 一定冲突。
* 叶子自制积木**互不调用**（结构验收保证），所以同一个 hat 调用到的过程可以**共用同一个寄存器池**；
  跨 hat 调用的过程单独一个池。

### 本轮抓到的两个真 bug（都是「静默错误」，不是崩溃）

1. **跨分支切分 web 不安全**：`如果…否则…` 两个分支各写一次同名变量，之后的读必须同时
   接上两个定义；按 def-use 硬切会把读接到后一个 web 上 → 递归用例直接死循环。
   修法：**只在同一个区域内切分**；站点跨区域时整个变量合成一个 web。
2. **跨循环回边共用寄存器不安全**：循环条件里读的变量（属于父区域）与循环体里的临时量
   （子区域）区间不重叠，会被分配同一个寄存器 —— 第二轮迭代时条件读到的是被覆盖的值。
   修法：① 混合规则里「区域可比较但不同 → 冲突」；② 额外把「循环头里有站点」或「循环前有站点」
   的 web 尾部**拉长到循环末尾**（实测触发 34 次）。

验证：`node _work/v5/run5.cjs` 全部 17 个套件 **242 例只剩 x19 一个已知失败**；
另外专门补了 6 个递归/嵌套调用/条件返回用例（`rec2.json`）逐条通过。

### 性能实测（注意：本机速度会漂移）

同一小时内**前后交替**测量才可比：新旧分配器 **15.7k vs 14.0~18.0k 指令/秒**，即分配器对速度**无影响**。
早先测到的 53k 是同一份文件在机器较快时测的 —— 跨时间比较不可信，已在文档里标注。
当前绝对水平：约 **16,000 指令/秒**，16 ms 时间片 ≈ **130 指令/帧**（§10 目标 5,000，**未达标**）。
## 第 20 轮

### 六处修改，第四套件 22/30 → 30/30

1. **增量赋值 `a[0] += k` / `c.n += k`**（上一轮回退的那条，这次做对了）。
   关键是把子节点求值顺序按字节码顺序写清楚：下标是 `obj, idx, obj, idx, SUBS, rhs, BIN, SUBSSET`，
   属性是 `obj, obj, GETATTR, rhs, BIN, SETATTR`（目标求值两次，这是栈机最省事的做法）。
2. **`del a[i]` / `del d[k]`**：新增指令 `DELIDX`（列表按下标左移；字典走 keyOf + 绑定链摘除）。
3. **`nonlocal` 之前是空实现**（`is('NONLOCAL', [])`）。现在把「帧号 + 名字」记进 `NlFr/NlName`，
   `STOREV` 命中时沿 map 父链（跳过本帧 map）找到绑定所在的作用域再写；`RET/RETN` 时按帧号剪枝。
   名字表要按逗号切分 —— 操作数里带尾逗号（`n|0,`），直接整串比对永远不相等。
4. **`print((lambda y: y+1)(4))` 静默不出结果**：解析器在 `)` 处只关闭 lambda 的 `M` 上下文，
   没有同时关掉外面那个括号的 `G/C` 上下文，于是后面的 `(` 被当成新的调用参数表，整个 call 节点错位。
   修法：`M` 关闭后若栈顶还是 `G`/`C`，同一个 `)` 继续把它关掉。
5. **元组/列表比较按堆 id 比**（`(2,'b') < (1,'a')` 为 True）：`cmpPair` 重写为统一的 -1/0/1 序，
   序列走 `seqOrder`（显式工作栈做逐元素字典序，代码生成器不能递归），标量走 `scalarOrder`；
   标量顺序比较整串标记文本（空串 `S` 与 `None` 的 `Z` 因此不会误判相等），字符比较在首个差异处停下（旧实现会被后面的字符覆盖）。
6. **类继承 `class B(A)`**：基类列表本来就在字节码常量里（常量格式是 `#<基类列表>#<类名>`），
   只是 `classBlock` 丢掉了。现在取两个 `#` 之间的部分、查全局表拿到基类，写入 `ClBase`，
   并让 B 的类 map 以 A 的类 map 为父 —— 实例属性查找自然沿 实例 → 类 → 基类 → 全局 走通。

### 本轮踩到的两个坑（写进文档免得再犯）

* `listRemoveAt(obj, ix)` 的第一个参数是**堆对象 id 表达式**，不是 Scratch 列表名；对 Scratch 列表要用 `S.ldel`，
  否则会生成 `item ("NlFr") of (LCount)` 这种畸形积木，构建期直接报 undefined op。
* 内核文件是 **CRLF/LF 混排**（早期补丁用 LF 写入）。按行匹配的补丁要么统一换行，要么两种都试。
