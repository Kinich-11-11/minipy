## 1. 运行输出从输出框顶部开始

**原问题**：点 RUN 后，控制台的最新生行固定在输出框第 7 行（输出框共 9 行），下面永远空 2 行，看起来像"从中间开始滚动"。

**修改**：Interpreter 的 `log` 过程里 `outpage = 输出行数 - 6` 改为 `outpage = 输出行数 - 8`。

**效果**：输出从第 1 行（顶部）开始向下铺满；超过 9 行后整体上滚，最新一行始终落在最后一行。测试：3 行输出 → outpage=1；20 行输出 → outpage=12（=20-8）。

## 2. 指针选区域 + 键盘 ↑/↓ 滚动（每次一行）

**规则**
1. **鼠标指针只决定"滚哪个区域"**，本身移动不会引起任何滚动（不再检测鼠标位移量）。
2. 在区域内按键盘 **↑ / ↓** → 该区域**滚动一行**；
   - ↑ = 往回看（上一行 / 上一页方向）
   - ↓ = 往后看（下一行）
   - 按住不放可连续滚动（键盘自动重复）。
3. **指针不在任何区域时，↑/↓ 保持原有编辑功能**（上下移动代码选中行、光标跟随），不会滚动任何面板。
4. 三个区域各自独立：滚控制台时变量区和代码页不动，反之亦然。

| 指针所在区域 | 位置 | ↑/↓ 滚动对象 |
|---|---|---|
| 控制台 CONSOLE | 右下侧整块面板 | `outpage`（输出，每页 9 行） |
| 变量区 VARIABLES | 右上侧整块面板 | `varpage`（变量列表，每页 4 行） |
| 代码区行号栏 | 左侧代码框最左边的行号窄条 | `page`（代码页，每页 16 行） |
| 其它位置（代码正文、按钮行等） | — | 不滚动，↑/↓ 仍是原来的编辑操作 |

隔离性保证（重要）：
- 每次按键都**重新判断指针所在区域**，区域编号是**作为参数传给滚动过程**的（不经过任何共享变量），因此两个方向键脚本、以及键盘自动重复造成的脚本重启，都不可能把滚动"串"到别的区域。
- 每个区域各自夹紧到自己的范围：滚到顶/到底后，**多余的按键不做任何事**（不会转去滚别的区域）。

补充说明：
- 代码正文区域故意**不**做滚动区，否则选中行时按方向键会变成翻页；代码页请把指针放到左侧行号栏再按 ↑/↓。
- 滚动与程序运行状态无关：程序正在刷输出时也能用 ↑/↓ 回看前面的输出。
- 到顶/到底会自动停住。
- 界面右侧的符号键盘（两行小按钮）点一下只插入一个符号；空出来的位置放了 Aa 大小写切换。

## 3. EXPORT 导出合并成一行

**修改**：Controller 的 `exportCode` 过程改为把整份代码用 `|` 连接后**只写入 Export 列表的 1 项**。

**效果**：点 EXPORT 后，Export 列表只有一行，例如：

```
name = 'Scratch'|print('Hello, ' + name)|total = 0|for i in range(1, 6):|    total = total + i
```

- 复制时一次就能把整份代码拿走。
- `|` 是本项目 IMPORT 约定的"换行符"，所以把这一行粘回 IMPORT 可以直接还原成多行程序（可无损往返）。
- 状态栏提示改为 `Export: whole program on 1 line ( | = newline )`；再点一次 EXPORT 仍然关闭 Export 列表。

## 4. 新增的 Python 语句 / 特性

### 4.1 多目标赋值与链式赋值

```python
a, b = 1, 2          # 元组式赋值
a, b = b, a          # 交换（先全部求值再赋值）
x, y, z = 10, 20, 30
p = q = 7            # 链式赋值
```

数量不匹配会报 `ValueError: unpack count mismatch`。

### 4.2 字符串下标与切片

```python
s = 'Python'
s[0]      # 'P'
s[-1]     # 'n'      支持负下标
s[0:3]    # 'Pyt'
s[3:]     # 'hon'
s[:2]     # 'Py'
s[-2:]    # 'on'
s[2:100]  # 'thon'   自动截断
s[n + 1]  # 下标可以是任意表达式
```

越界报 `IndexError: string index out of range`。

### 4.3 for 遍历字符串

```python
for ch in 'Scratch':
    print(ch)
```

`for i in range(...)` 的 1~3 参数写法保持原样；`break` / `continue` 在字符串循环里同样有效；空字符串循环体不执行。

### 4.4 新增内置函数

| 函数 | 说明 |
|---|---|
| `max(a, b)` / `min(a, b)` | 取大 / 取小 |
| `pow(a, b)` | 幂运算，指数需为整数，支持负指数（如 `pow(2, -1)` → 0.5） |
| `round(x, n)` | 保留 n 位小数，支持负 n（如 `round(1234, -2)` → 1200） |
| `ord(c)` | 字符 → ASCII 码（区分大小写） |
| `chr(n)` | ASCII 码 → 字符（32~126） |

原有的 `print / input / len / str / int / float / bool / abs / round(x)` 全部保持不变。

### 4.5 `not in` 运算符

```python
if 'xyz' not in s:
    print('ok')
```

优先级与 Python 一致（和 `in`、`==` 同级，低于 `and` / `or`）。

### 4.6 DEMO 与 HELP 更新

- HEY/DEMO 按钮现在循环 4 个示例，第 4 个示例演示解包赋值、下标、切片、字符串循环、`not in`、`max`、`pow`。
- HELP 文本更新为当前支持的功能列表。

### 5.4 顺带修正：in / not in 改为大小写敏感
原来 `in` 用的是 Scratch 的"包含"积木，**不区分大小写**（`'M' in 'abc…z'` 会误判为真，与 Python 不一致）。现在改为逐位置用本项目的 `compareText` 做**大小写敏感**比较，和 Python 完全一致：

```python
'Hello' in 'Hello World'   # 1
'hello' in 'Hello World'   # 0
'Z' not in 'Hello World'   # 1
'' in 'abc'                # 1
```

## 7. 本轮：按评审建议做的修改

参照 `MiniPy_v4_评审建议.md` 逐条落地（改的仍是 `_work/build.js`，可重放生成）。

### 7.1 性能（P0）

| 项 | 原来 | 现在 |
|---|---|---|
| **运行速度** | RUN 主循环每执行一行就 `wait 0`，上限 30 行/秒 | 新增 **速度开关**：快速模式每 50 行才让出一帧并重绘，慢速模式仍逐行刷新。实测 60 行程序 **快速 5 帧 / 慢速 61 帧（约 12 倍）** |
| **变量查找** | 每次读写变量都逐字符切造型比较 | 先比长度、再用内建 `=` 粗筛，只有可能相等时才调 `compareText` 精筛（语义不变，大小写仍然敏感） |
| **步数上限** | 固定 10000 | 慢速 10000 / 快速 100000，按速度自动放宽；报错文案改为 `LimitError: step limit reached` |

速度开关放在符号键盘最后一个空位，按钮写作 **`>>`**（点一下切换，状态栏显示 `Speed FAST (>> lit)` 或 `Speed SLOW`），默认快速。

### 7.2 安全上限（P0-4）

`pow(2, 100000)`、`round(1.5, 999)` 这类极端参数原来会在**一帧内**跑十亿次循环把浏览器卡死。现在：

* `pow` 指数绝对值 > 1024 → `ValueError: pow() exponent too large`
* `round(x, n)` 的 n 绝对值 > 15 → `ValueError: round() ndigits out of range`

### 7.3 格式与清理（P1）

* **parent 反向链接全部补齐**：写入前统一重算，本次修正 **1214 处**（评审时统计缺失 524 处）。校验结果：悬空引用 0、非顶层积木缺 parent 0、顶层积木误带 parent 0。
* 删除 v3 遗留的常量死分支 `if 1 == 0`（1 处）。
* 删除全工程未被引用的变量声明 **16 个**（uj、rk、ry、rtext、eprec、tail、nest、start、end、alt、linebody、argstart、c1、c2、oldv、oldtype），变量总数 120 → 104。

### 7.4 长行 / 粘贴 / 竖线（P1-3 + P2-1）

* 把原本悬空的 **`editLine` 过程接回来了**：在左侧**行号栏双击**（0.5 秒内两次）即弹出输入框，可粘贴/改写整行；答 `:cancel` 放弃（编辑自带一次 undo 快照）。
* **IMPORT 支持转义**：`\|` 表示行内的字面竖线，单独的 `|` 仍然分行，所以 `print('a\|b')` 这类代码可以无损往返。HELP 里加了一行说明。

### 7.5 控制台不再"抢滚动"（P2-4）

原来每打印一行都把 `outpage` 拉到底部，用户往回翻会被顶回来。现在加了**跟随判定**：只有视图本来就在底部附近才跟随；往回看时新输出不再打断阅读（实测：暂停在 `input()` 时把视图翻到第 5 行，程序继续打印后仍停在第 5 行）。

### 7.6 与 Python 的差异修正（P2-3 部分）

* **表达式深度上限 24 → 64**：原来 25 项以上的连加会误报 `LimitError: expression depth`，现在 30 项连加正常（实测输出 465）。
* 仍需注意（已在文档说明，未改实现）：`round(0.5)` 用 JS 的 .5 进位而非银行家舍入、`True` 打印为 1、字符串里的 `\n` 不转义成换行、`int(' 12 ')` 不接受空白、`range` 只支持整数步长；单行 240 字符 / 程序 200 行 / 值 2048 字符 / 控制台 300 行的上限也保持不变。

### 7.7 自测中发现并修复的问题

加完性能补丁后自测时发现变量读取会**死循环**（一帧 500 ms、程序卡住）。原因是 lookup 预筛补丁用"替换所有指向 compareText 的引用"的方式插入判断，结果把判断自己的 SUBSTACK 也指回了自己，同时把循环体后半段（`found++`）挤成了孤立积木。现已改成"在 compareText 原来的位置上做拼接、并保留后续链"，变量读取恢复正常（`'b' in s` 这类带变量的表达式 13 ms/帧）。

### 7.8 未做的（评审路线图里的大件）

`def` 自定义函数、Python 列表、中文（非 ASCII）输入与渲染、`try/except`——这些属于新功能而非修补，需要成套改动（分词器、渲染回落、类型系统），本轮没有动。

另外评审提到的"符号键盘分派与 insert 共用变量 ui"已在上一轮修掉；"变量区超 30 字硬截断""undo 只有一级""控制台 300 行上限""EXPORT 不导出控制台"这几项维持原样（属于体验增强，未改）。

测试 harness 已随工程保存到 `_work/tests/`（含 README），可用真实 scratch-vm 复现全部回归。

   | 语法 | 说明 |

## 8.1 Python 列表（本轮已合入）

**实现方案**：不引入新的存储/句柄，列表值就是一段“编码字符串”——`分隔符 + 类型字符 + 元素原文` 重复若干次（空列表 = 空串），值的类型标记统一用 `L`（与既有 `N`/`S` 并列）。分隔符取 ASCII 31（变量 `lsep`）。这样列表天然能存进变量、被赋值、当参数传递，不必改解释器的值模型。

新增 4 个自制积木：`listlit`（把源码下标区间里的元素逐个 `eval` 后编码）、`listlen`（数分隔符）、`listitem(s, idx)`（1 起，返回元素值 + 元素类型）、`listfmt`（渲染成 `[a, b, c]`）。

| 已支持 | 例子 | 结果 |
|---|---|---|
| 字面量 / 空列表 | `a = [3, 1, 2]`、`[]` | — |
| 打印 | `print(a)` | `[3, 1, 2]` |
| 长度 | `len(a)` | `3` |
| 求和 | `sum([1, 2, 3, 4])` | `10`（元素必须是数字，否则 TypeError） |
| 转字符串 | `str(a)` | `[3, 1, 2]` |
| 下标（含负数） | `a[0]`、`a[-1]` | `3`、`2`；越界报 `IndexError: list index out of range` |
| 遍历 | `for x in a:` | 逐个元素，元素类型自动回填 |
| 追加 | `a.append(x)` | 就地追加（返回 None） |
| 弹出 | `a.pop()` | 返回并删除最后一个元素；空列表报 `IndexError: pop from empty list` |
| 拼接 | `a.extend(b)` | 把列表 b 的元素接到 a 后面 |
| 清空 | `a.clear()` | a 变成 `[]` |
| 表达式语句 | `a.append(1)` 单独一行 | 整行当表达式求值后丢弃结果（以前只有 `print(...)` 能单独成句） |
| 元素赋值 | `a[i] = v` | 就地改写第 i 个元素（支持负数下标）；越界报 `IndexError: list assignment index out of range` |
| 混合类型 | `a = [1, "b", 3]` | 打印 `[1, b, 3]`，遍历时 x 依次是数字/字符串/数字 |

**尚未支持（下一步）**：`del a[i]`、`a.insert/remove/index/count/sort/reverse`、`a + b`、`min(a)/max(a)`、嵌套列表、列表推导式、切片 `a[1:2]`。`a[i] = v` 要接进 `assign`（先按 `listitem` 的扫描定位元素起止，再用 `substr` 拼回）；`listfmt` 目前不区分元素类型，等做 repr 时再给字符串元素补引号。

**本轮排错实录（三次真实 bug，供后续参考）**：

1. `printargs` 的逗号扫描只跟踪 `(` `)`、不跟踪 `[` `]`，于是 `print([1, 2])` 被切成两个参数 → 给该扫描补上同 `eval` 一样的方括号深度判断。
2. eval 里的“列表字面量”分支必须挂在 `A[i]` 下标分支**所在的槽位**上（用 `indexget` 调用块反查父块最稳），不要用结构启发式搜索——一开始误把 `indexget` 扫描循环里另一个 `xcol = 0` 的 if 当成了派发块，导致字符串下标分支照旧执行（`a[0]` 打印出编码串的第一个字符）。
3. `listitem` 取元素时多加了 1：搜索循环退出时 `li` 已经等于 `lstart + 1`，再 `+1` 就跳过类型字符，只能取到元素的最后一个字符。

另外：新增积木的 `parent` 指针要在**所有**补丁之后再统一重挂一次（补丁 13d），否则会留下 137 个“有引用但无 parent”的孤儿积木（结构校验会报 non-top blocks without parent）。

## 8.2 表达式语句与列表方法（本轮）

1. **表达式语句**：以前只有 `print(...)` 这类语句能单独成行，`len('ab')` 或 `a.append(1)` 单独一行会报 “SyntaxError: unsupported statement”。现在 `execute` 末尾那条“待处理标记 `pending` 仍为 0 → 报不支持”的分支改成：先查关键字黑名单（`import/from/def/class/try/except/finally/with/lambda/yield/global/nonlocal/raise/as/elif/else/return/pass/async/await`），命中才报原来的错误，否则把整行当表达式求值并丢弃结果。这样既支持了 “调用后不管返回值” 的写法，又没有把 `import os` 这类真正没实现的语句静默吞掉（实测仍报 unsupported statement）。
2. **列表方法**：在 `eval` 的派发阶梯里，`名.方法(...)` 被路由到新过程 `methodcall %s %s`（接收者取 `Tok[lo]`、方法名取 `Tok[lo+2]`、参数区间 `lo+4 .. hi-1`，因为分词器把 `.` 切成独立记号：实测 `b = a.foo(2)` 的 Tok 是 `[b,=,a,.,foo,(,2,)]`）。实现的方法是 `append / pop / clear / extend`；`pop` 靠 `substr(xa, 1, 末分隔符-1)` 截断编码串，`extend` 直接拼接两段编码串（同一套分隔符/类型标记，天然可拼）。

**元素赋值（下标赋值）的实现**：新增过程 `indexset`（参数 lo/hi），`execute` 里加一条“第 1 个记号是名字、第 2 个记号是左方括号”的分支（放在“待处理标记 pending 仍为 0”那个兜底分支之前），把整行交给 indexset 解析：用深度法找配对的右方括号 → 求值接收者 / 下标 / 右值 → 边界检查 → 数分隔符定位该元素的起止 → 用两段 substr 拼回新的编码串 → assign 写回列表。

本轮又踩两个坑：① 括号配对扫描要从 lo+1（左方括号本身）开始，从 lo+2 开始会让深度只减不增、永远配不上；② 分支处理完必须置 pending = 1，否则会继续掉进同一个兜底分支、把整行再当表达式求值一次（表现为前面明明算对了，最后却报 SyntaxError: expression）。

踩过的坑：① `execute` 里那个报错点藏在 `if pending = 0` 的 SUBSTACK 里，要按 “fail 调用 + 错误文本” 反查再整块替换；② 接收者取值直接复用 `eval(lo, lo)`（单记号求值）比调 `lookup` 更省事；③ 同一个 argument reporter 积木不能同时喂两个输入（parent 只能有一个），所以 `lo/hi` 一律写成工厂函数按需新建；④ 补丁文件（`p13c.txt`）改了以后必须重跑 `fixer35` 重新拼接，`fixer36` 只负责追加 p14 —— 只跑后者会让改动“看着改了其实没进构建”。
